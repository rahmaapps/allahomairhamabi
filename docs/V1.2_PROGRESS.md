## Phase 9 — investigation détaillée (Share as image)

**Chemin retracé :** bouton (icône AppBar "تصدير الدعاء كصورة" OU nouveau bouton "مشاركة كصورة" en bas d'écran, même méthode `_openTemplatePicker`) → sélection template dans le bottom sheet → `setState(_selectedTemplate)` + `Navigator.pop` + `_sharePremiumImage()` → `_renderPremiumPng()` → `boundary.toImage()` → `Share.shareXFiles([un seul fichier])`.

**Widget capturé avant correction :** chaque page de `PremiumExportCard.buildPages()`, une `RepaintBoundary` par page, dans un `Column`, lui-même enfant d'un `Offstage(offstage: true, ...)` — enfant direct (non positionné) du `Stack` racine.

**Cause réelle confirmée (source du framework Flutter, pas une supposition) :** `RenderOffstage.paint()` retourne immédiatement sans jamais appeler `super.paint()` quand `offstage == true`. Le sous-arbre est bien **layout** (Offstage force toujours le layout de son enfant — les dimensions sont donc valides) mais **jamais peint/composité**. Une `RenderRepaintBoundary` jamais peinte n'a pas de layer composité exploitable par `toImage()`.

**Preuve corroborante trouvée dans le code lui-même :** le même fichier contient un second mécanisme de capture hors-écran plus ancien ("Option A", `_imageKey`, désactivé) qui utilise délibérément `IgnorePointer > Opacity(opacity: 0.01)` — **pas** `Offstage` — précisément parce qu'`Opacity` continue de peindre son enfant (à une valeur quasi nulle) alors qu'`Offstage` ne le fait jamais. Le mécanisme de pagination introduit ultérieurement avait divergé de ce pattern déjà établi dans le projet.

**Correction retenue (minimale, alignée sur la décision produit "une seule image toujours") :**
1. `Offstage` → `IgnorePointer(child: Opacity(opacity: 0.01, child: RepaintBoundary(...)))` — même pattern déjà prouvé dans ce fichier.
2. `_exportKeys` (liste) + `premiumPages` (calcul dans `build()`) + boucle `Column` → un seul `GlobalKey _exportKey` + un seul `RepaintBoundary` enveloppant directement `PremiumExportCard(template: _selectedTemplate, duaText: _currentDuaText, ...)`. `PremiumExportCard.build()` restreint déjà lui-même le rendu Dark Luxe paginé à sa première page (`buildPages(...).first`) — **aucune modification de `premium_export_card.dart` ni `premium_dua_paginator.dart`** : leur comportement existant, non touché, satisfait exactement "toujours une seule image".
3. `_renderPremiumPngPages()` (`List<Uint8List>?`) → `_renderPremiumPng()` (`Uint8List?`), même patron capture/retry.
4. `_sharePremiumImage()` → partage toujours exactement un `XFile`.
5. Bouton "تقييم التطبيق" (bas d'écran) retiré, remplacé par "مشاركة كصورة" → `_openTemplatePicker`. `_rateApp()` **conservé** (non supprimé, juste non appelé) pour intégration dédiée future — décision produit déjà validée.
